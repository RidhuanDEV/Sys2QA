# Sys2QA Analyst: commands and tool calls

Every CLI command is one application-service operation, and every MCP tool is the same operation with the same input
(Architecture §8). `<…>` marks a value you take from an earlier result; IDs are always generated by Sys2QA, never
invented. Add `--json` to a CLI command for the machine-readable result (the same object an MCP tool returns).

The conformance test (`tests/conformance/skill.test.ts`) checks every example below against the current operation
catalog: each command must resolve to an operation the Skill declares, and each tool call must match the operation's
input schema.

## Person's steps (CLI only)

Registering a repository and authorizing its analysis are decisions of the person who owns it. Ask them to run:

```sh
sys2qa start "Acme portal" ./path/to/repository
sys2qa declare <source-id> --level L1 --by <your-name>
```

## Compatibility

```sh
sys2qa capabilities --skill skills/sys2qa-analyst
sys2qa info
sys2qa adapters
```

```json
{ "tool": "system.capabilities", "arguments": { "requires": { "capability_version": 1, "operations": [] } } }
```

Pass the whole `requires` object of `capabilities.json`; the empty list above only shows the shape.

## Orient and analyze

```sh
sys2qa project list
sys2qa status <project-id>
sys2qa analyze <source-id> --profile standard
```

```json
{ "tool": "project.list", "arguments": {} }
{ "tool": "saa.status", "arguments": { "project_id": "<project-id>" } }
{ "tool": "saa.analyze", "arguments": { "source_id": "<source-id>", "profile": "standard" } }
```

## Overview and workflows

```sh
sys2qa workflows list <run-id>
sys2qa workflows list <run-id> --category api
sys2qa workflows show <run-id> <workflow-id> --language id
sys2qa trace <run-id> <workflow-id>
sys2qa trace <run-id> <workflow-id> --deepen
```

```json
{ "tool": "saa.overview", "arguments": { "run_id": "<run-id>" } }
{ "tool": "saa.workflows.list", "arguments": { "run_id": "<run-id>", "category": "user_interface" } }
{ "tool": "saa.workflows.show", "arguments": { "run_id": "<run-id>", "workflow_id": "<workflow-id>", "language": "en" } }
{ "tool": "saa.trace", "arguments": { "run_id": "<run-id>", "workflow_id": "<workflow-id>", "deepen": true } }
```

## Export and hand off

```sh
sys2qa export <run-id>
sys2qa validate <package-path>
```

```json
{ "tool": "saa.export", "arguments": { "run_id": "<run-id>" } }
{ "tool": "package.validate", "arguments": { "path": "<package-path>" } }
```

## Exit codes (CLI)

0 ok; 1 internal; 2 usage or invalid input; 3 denied (`SCOPE_DENIED`, `DECLARATION_REQUIRED`); 4 not found; 5
conflict (`EXPORT_REFUSED`); 6 unavailable (`ADAPTERS_UNAVAILABLE`, another host holds the state, or `capabilities
--skill` found an incompatibility).
